# 04 Case 故事库模板

## 来源

本文件的 STAR 公式与故事框架直接来自用户的[实习框架](../实习框架) Step 2 与 Step 3。遇到分歧以原文为准。

## 两类故事

### 类型 A：困难闭环（推动力）

适合"我推动了一件大家都觉得难推的事"的故事。

| 段落 | 内容 |
|---|---|
| 卡点 | 卡的是什么（人 / 资源 / 认知 / 机制 / 数据）。要具体到"为什么这是个难题" |
| 拆解 | 把大问题拆成 2-4 个小问题。每个小问题独立可推进 |
| 推动 | 你做了什么（对齐 / 评审 / 跨团队拉人 / 数据论证 / 灰度方案）。突出**个人贡献的具体动作** |
| 结果 | 量化 + 归因。指标提了多少，是不是你的方案带来的（AB / 灰度 / 对照） |
| 方法论 | 这件事抽象出的可复用经验（1 句话） |

### 类型 B：认知反转（思考力）

适合"我一开始判断错了，后来通过证据改变了策略"的故事。

| 段落 | 内容 |
|---|---|
| 初始假设 | 我最初的判断是什么。当时的依据为什么合理（不能写成"我蠢"，要写"基于当时已知信息这是合理判断"） |
| 推翻证据 | 哪些数据 / 反馈 / 案例让我意识到错了 |
| 调整 | 我怎么快速调整：新的假设 + 新的方案 + 新的验证策略 |
| 结果 | 量化 + 归因 |
| 方法论 | 抽象出的判断改进规则（1 句话） |

## 写作公式（两类通用）

```
遇到 [什么卡点 / 什么误判]
  → 进行了 [什么多维分析 / 什么数据复盘]
  → 采取了 [什么具体行动]
  → 结果如何（量化 + 归因）
  → 形成了 [什么方法论]
```

## 文件命名

`case_<类型>_<2-4字关键词>.md`

例：
- `case_困难闭环_长记忆方案落地.md`
- `case_认知反转_角色一致性方向调整.md`

## 写好的判断标准

一个 case 写完后，自检：

- [ ] 1 分钟内能讲完口述版
- [ ] 数据可量化、可归因
- [ ] 个人贡献和团队贡献分得清
- [ ] 至少能扛 3 层追问
- [ ] 与 02/03 层的双链都验证过（点进去文档存在且相关）
- [ ] 有 1 句可复用的方法论

## 常见误区

- **只讲"做了什么"不讲"为什么这么做"**：面试官会追问取舍逻辑
- **结果只有"上线了"**：没数据 = 没结果。哪怕 AB 没跑，也要给"用户访谈/客诉变化/同事反馈"的定性证据
- **冒认团队功劳**：写"我推动 X 决策"时，必须能答清"如果没有你这件事会怎么样"
- **故事太大**：一个 case 时间跨度尽量 2-4 周。半年的大项目要拆成多个 case
- **避而不谈失败教训**：reflection 里没有"如果重来"的回答会显得很浅
