# 03 前后端研发层模板

## 适用场景

记录系统架构、接口、关键模块、工程实践、性能/成本指标等"研发视角"内容。

## 必备条目清单

### 系统架构.md

- 整体架构图（文字版）：客户端 → 网关 → 业务服务 → 算法服务 → 模型网关 → 模型
- 关键中间件：消息队列 / 缓存 / 向量库 / DB / 监控
- 部署形态：单云 / 多云 / 边缘
- 流式 vs 非流式的链路差异
- 与外部依赖（云厂商 / 第三方 API）的边界

记录格式：
```
[Client iOS/Android/Web]
       ↓ HTTPS
[API Gateway]
       ↓
[Conversation Service] ←→ [Cache: Redis]
       ↓
[Prompt Builder] ←→ [Memory Service] ←→ [Vector DB]
       ↓
[Model Gateway]
       ↓
[LLM (xxx 4.7 / xxx 自研)]
```

### 关键接口.md

按"上下游交付物"组织。每个接口：
- 名称与路径
- 入参 / 出参（核心字段）
- 调用方 / 被调用方
- QPS / 延迟 SLA
- 错误处理策略

不需要把所有接口都写，只写**对话核心链路**和**用户能感知到延迟**的接口。

### 关键模块.md

C 端 Agent 产品常见的关键模块（按你的项目实际情况选）：

#### 人设引擎
- 人设数据结构（角色卡 / 知识 / 关系 / 时间线）
- 人设加载与切换
- 人设一致性约束（system prompt + RAG + 后处理）

#### 记忆系统
- 短期记忆（窗口管理 / 摘要压缩）
- 长期记忆（vector DB / 用户画像 / 重要事件）
- 记忆检索（相似度 / 时间衰减 / 重要性加权）
- 记忆写入策略（实时 / 异步 / 用户授权）

#### 对话状态机
- 对话上下文如何维护
- 多轮 / 多角色 / 多场景的状态切换
- 异常态恢复

#### 路由与编排
- 多模型路由（按场景 / 成本 / 延迟）
- Tool Use 编排
- 流式输出与中断

#### 安全与合规
- 输入预过滤
- 输出二次过滤
- 敏感场景熔断
- 用户举报回流

### 工程实践.md

- 评估流水线（怎么集成进 CI）
- 灰度策略（按用户 / 按比例 / 按场景）
- AB 框架（用什么工具 / 怎么打点 / 怎么显著性检验）
- 监控指标（延迟 P50/P99 / 错误率 / token 消耗 / 模型质量分）
- 日志与回放（出问题时怎么定位）
- 分支策略与发布节奏

### 性能与成本.md

- 关键性能 SLA（首 token / 总响应 / 流式 chunk 间隔）
- 单次对话 token 消耗（输入 / 输出 / 缓存命中率）
- 单次对话成本（按模型分摊 / 按服务分摊）
- 成本优化点（prompt 压缩 / 缓存 / 小模型路由 / 蒸馏）
- 容量规划（峰值 / 弹性 / 降级方案）

## 填写约束

- **不要硬塞代码**：关键模块条目里偶尔贴关键片段是 OK 的，但不要把整个文件复制进来
- **对外 vs 对内**：模块的"外部约定"（接口/数据结构）和"内部实现"（算法/优化）分两段写
- **隐患透明化**：知道有问题但暂时没修的，写 `// 已知问题：xxx，待 v2.x 处理`，不要装作没事
